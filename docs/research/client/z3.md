> Synthesis of 4 research reports (stack, Zaino, wallet, protocol/mainnet). Nothing here was run yet; every step is from sources at the cited commits. Raw reports: `/private/tmp/claude-501/-Users-oynozan-Desktop-Dev-Web3-z402/c930aa64-2dab-492b-a2a2-942f84f5d85a/scratchpad/z3-report-*.md`.


## 0. Decisions in one screen

- **Z3 is real and fits, with corrections.** The repo is `github.com/ZcashFoundation/z3`. It has no tags and no releases; HEAD is `e84ce9fd8e864ff0b2a8a62f6ce14392145db0fb` (2026-08-10). The default stack is **Zebra + Zallet**. **Zaino is opt-in** (`--profile indexer`), and lightwalletd is not part of it. Regtest needs no faucet: you mine on demand with Zebra's `generate` and `generatetoaddress`.
- **Regtest runs NU6.3 (Ironwood), not NU7.** This is the right choice. Mainnet stays on NU6.3 until about 2026-11-05/06, which is after the deadline. So regtest takes the same path the mainnet demo will: v6 transactions, Ironwood pool, branch `0x37a5165b`.
- **Agent wallet on regtest:** Zallet over JSON-RPC. It ships with the stack, uses the same activation heights as Zebra, and its send path was exercised upstream.
- **Agent wallet on mainnet:** zingo-cli `0a5cb69` nakednet against a public lightwalletd. Zallet on mainnet would need a fully synced node of about 300 GB, which takes 24–72 h.
- **Facilitator chain endpoint on regtest:** Zaino at `http://127.0.0.1:28137` (plaintext h2c). **Override the image to `zingodevops/zainod:0.10.2-no-tls`.** Z3's pinned 0.6.0 reports a mempool transaction at the tip height.
- **Merchant payTo and UIVK:** generate them with our own `zdecrypt keygen` once it takes a network switch, not with Zallet. Zallet beta.1 cannot export a UIVK.

## 2. Recipe: Z3 regtest on macOS arm64, first deposit

Nothing below has been run. Every step comes from the sources.

```bash
# 0. Checkout
git clone https://github.com/ZcashFoundation/z3 ~/z3 && cd ~/z3
git checkout e84ce9fd8e864ff0b2a8a62f6ce14392145db0fb

# 1. Init: copies config/regtest/*.toml, generates the Zallet pwhash, starts Zebra, mines 2 blocks
#    (activates NU6.3), runs generate-encryption-identity, init-wallet-encryption and
#    generate-mnemonic, then stops Zebra (scripts/regtest-init.sh L161-223)
./scripts/regtest-init.sh

# 2. Before Zallet's first start: create account 0 and a transparent miner address
#    (works only on a wallet that has never started; Zallet
#    zallet-core/src/commands/regtest/generate_account_and_miner_address.rs L33-38)
MINER=$(docker compose --env-file .env.regtest run --rm --no-deps -T zallet \
  --datadir /var/lib/zallet --config /etc/zallet/zallet.toml \
  regtest generate-account-and-miner-address | tail -n1)          # tm…

# 3. Precaution. beta.1's keystore.require_backup defaults to true (Zallet beta.1 config.rs L636, L658-659).
#    Under [keystore] in config/regtest/zallet.toml add:
#      require_backup = false

# 4. Start the services, skipping the rpc-router build. Zaino gets the fixed image.
export Z3_ZAINO_IMAGE=zingodevops/zainod:0.10.2-no-tls
docker compose --env-file .env.regtest up -d zebra zallet
docker compose --env-file .env.regtest --profile indexer up -d zaino

Z='curl -s -u zebra:zebra -H content-type:application/json http://127.0.0.1:29232 -d'
W='curl -s -u zebra:zebra -H content-type:application/json http://127.0.0.1:50232 -d'

# 5. Fund: transparent coinbase to Zallet. Transparent coinbase needs 100 confirmations,
#    so 110 blocks leaves about 10 mature UTXOs.
$Z '{"jsonrpc":"2.0","id":1,"method":"generatetoaddress","params":[110,"'$MINER'"]}'
$W '{"jsonrpc":"2.0","id":1,"method":"z_listaccounts","params":[]}'                         # -> account uuid
$W '{"jsonrpc":"2.0","id":1,"method":"z_getaddressforaccount","params":["<uuid>",["orchard"]]}'  # -> uregtest1… AGENT_UA
$W '{"jsonrpc":"2.0","id":1,"method":"z_shieldcoinbase","params":["'$MINER'","<AGENT_UA>",null,10]}'   # -> opid; lands in Ironwood
$W '{"jsonrpc":"2.0","id":1,"method":"z_getoperationresult","params":[["<opid>"]]}'
$Z '{"jsonrpc":"2.0","id":1,"method":"generate","params":[1]}'
$W '{"jsonrpc":"2.0","id":1,"method":"z_getbalanceforaccount","params":["<uuid>",1]}'  # pools.ironwood.valueZat > 0

# 6. Merchant keys (after the zdecrypt patch in §5)
zdecrypt keygen --network regtest     # orchardOnlyAddress = payTo (uregtest1…), uivk = facilitator key (uivkregtest…/uviregtest…)

# 7. Block clock. Without it nothing confirms or expires, and the not-found "dead" rule never fires.
while true; do $Z '{"jsonrpc":"2.0","id":1,"method":"generate","params":[1]}' >/dev/null; sleep 25; done &

# 8. One memo deposit (the memo is hex of the UTF-8 text)
MEMO=$(printf '%s:0' "$SESSION_KEY_HEX" | xxd -p | tr -d '\n')
$W '{"jsonrpc":"2.0","id":1,"method":"z_sendmany","params":["<AGENT_UA>",[{"address":"<payTo>","amount":"0.001","memo":"'$MEMO'"}],1,null,"FullPrivacy"]}'
$W '{"jsonrpc":"2.0","id":1,"method":"z_getoperationresult","params":[["<opid>"]]}'   # result.txid

# 9. Check the deposit as the facilitator sees it (TxFilter.hash = byte-reversed txid)
H=$(echo $TXID | fold -w2 | tail -r | tr -d '\n' | xxd -r -p | base64)
grpcurl -plaintext -import-path lightwallet-protocol/walletrpc -proto service.proto \
  -d '{"hash":"'$H'"}' 127.0.0.1:28137 cash.z.wallet.sdk.rpc.CompactTxStreamer/GetTransaction
```

**Ports** (`.env.regtest` L22-39):

| Service | Host port | Auth / notes |
|---|---|---|
| Zebra RPC | 29232 | Cookie auth is off. `zebra:zebra` is harmless. |
| Zallet RPC | 50232 | Basic `zebra:zebra` |
| Zaino gRPC | 28137 | Plaintext h2c |
| Zaino JSON-RPC | 28237 | |

The host ports are published on all interfaces.

**Optional shortcut (unverified):** run `generatetoaddress [n, AGENT_UA]` instead of steps 5 and 6. Coinbase then lands directly in Ironwood with no consensus maturity (ZIP 213). It is unknown whether Zallet picks up shielded coinbase, and each such block takes seconds to prove.

## 3. Wallet adapter for z402

**Recommendation: one `WalletAdapter` interface with two implementations.**
- `ZalletRpcAdapter`: build it now, for regtest.
- `ZingoCliAdapter`: build it once the app works end to end, for mainnet.

Zallet is the fastest route to a first deposit. zingo-cli on regtest carries three unknowns: a nakednet build that has never sent, an activation-height mismatch, and a sync against Zaino that zingolib's CI stopped testing on 2026-10-15.

**ZalletRpcAdapter.** It speaks JSON-RPC 2.0 over HTTP to `http://127.0.0.1:50232` with Basic `zebra:zebra`. Method signatures are from Zallet beta.1 `methods.rs`.

1. **`send({payTo, amountZat, memo})`**
   - Call `z_sendmany [AGENT_UA, [{address: payTo, amount: zatToZecString(amountZat), memo: Buffer.from(memo,"utf8").toString("hex")}], 1, null, "FullPrivacy"]`. It returns an opid.
     - `fee` must be null ("Zallet always calculates fees internally; the fee field must be null.", `z_send_many.rs` L147-150).
     - The memo must be hex ("Invalid parameter, expected memo data in hexadecimal format.", `payments.rs` L579-593).
     - Build the amount string from a BigInt, never a float.
   - Poll `z_getoperationresult [[opid]]` every 250 ms.
     - `status:"success"` gives `result.txid` (or `result.txids[0]`).
     - `"failed"` gives `error.message`.
   - **Persist the txid immediately.** Opids live in memory and are lost when Zallet restarts (`get_operation.rs` L38-60).
2. **`findSentByMemo(memo)`**, used for §9 step 7 recovery.
   - Call `z_listtransactions [uuid]` and keep rows where some output has `memo === memo && !is_change`.
   - `mined_height === null` means pending; `expired_unmined` means dead.
   - Unverified for outputs sent to an external address.
3. **`spendableZat()`**: call `z_getbalanceforaccount [uuid, 1]` and add `pools.ironwood.valueZat` and `pools.orchard.valueZat`.
4. **Tip:** Zebra `getblockcount`, or `getwalletstatus.node_tip.height`.

**ZingoCliAdapter (mainnet).** This is the existing plan: one `execFile` per operation with `RUST_LOG=off NO_COLOR=1`:
- `zingo-cli --chain mainnet --server https://<endpoint>:443 --data-dir <d> --waitsync quicksend '[{"address","amount","memo"}]'`
- Recovery: `--offline messages "<memo>"`

If you pass `--server` explicitly, the nakednet build uses it as given and skips the server survey (`zingo-cli/src/server_select_nakednet.rs` L160-178).

## 5. Facilitator side

- **zdecrypt hardcodes `pub const NETWORK: Network = Network::TestNetwork`** (`crates/zdecrypt/src/lib.rs` L42). It is used by:
  - `decode_key` (L97, L114)
  - `decode_ua` (L288)
  - the encode calls (L148-165, L447-452)
  - `BranchId::for_height` (L235, L401)
  - `zip212_enforcement` (L199)

  As it stands it **rejects `uivkregtest`/`uviregtest`**. The fix:
  - Make the network a runtime choice: `--network regtest|test|main` or `ZDECRYPT_NETWORK`.
  - Back it with an enum that delegates `Parameters` to `MainNetwork`, `TestNetwork` and `LocalNetwork`.
  - Enable `zcash_protocol = { version = "=0.11.0", features = ["std","local-consensus"] }`.
  - Use this regtest value:
    ```rust
    LocalNetwork { overwinter: h(1), sapling: h(1), blossom: h(1), heartwood: h(1), canopy: h(1),
      nu5: h(2), nu6: h(2), nu6_1: h(2), nu6_2: h(2), nu6_3: h(2), nu7: None }
    ```
    (`local_consensus.rs` L41-56)
  - `testbuild.rs` L63 requires `BranchId::Nu7`. Allow `Nu6_3` there for regtest.
- **Decryption does not change.** Trial-decrypt both `orchard_bundle()` and `ironwood_bundle()`; the code already does this at L224-228. For v5 and v6, `Transaction::read` takes the branch from the header.
- **gRPC:** `@z402-net/lightwalletd` must:
  - use `grpc.credentials.createInsecure()` for `http://127.0.0.1:28137`;
  - use the not-found matcher from §4;
  - keep `TxFilter.hash` byte-reversed (Zaino uses the same convention, 0.10.2 L1283-1293).
- **Polling:** keep the `GetLatestBlock` poll at 5 s. The deadlines and the 120 s / 2-block not-found rule work only while the block clock runs.

## 6. Mainnet migration checklist

**NU7 activates on mainnet after the deadline.** At about 14:51 UTC on 2026-10-27 the tip was about 3,532,520. NU7 activates at 3,543,405 (`zcash_protocol` 0.11.0 `consensus.rs` L567). That is 10,885 blocks at 75 s, about **2026-11-05/06**. A mainnet demo before then runs on NU6.3 rules, which regtest already exercises.

1. Set the config: `network = zcash:mainnet`. payTo must match `u1|zu1` (already in code).
2. Generate merchant keys with `zdecrypt keygen --network main` from a fresh seed kept out of the repo. Give the facilitator the `uivk…`/`uvi…` key.
3. Endpoint: `zec.rocks:443` (TLS), or the regional `na|eu|ap|sa.zec.rocks:443`. All were probed on 2026-10-27 and reported `main` and branch `37a5165b`.
   - Prefer one regional host for both wallet and facilitator, so first sight is consistent.
   - Keep both not-found matchers, because zec.rocks mixes Zebra 7.0.0 and Zakura backends.
   - Whether `zcash.mysideoftheweb.com:9067` uses TLS was not recorded.
4. Wallet: zingo-cli `0a5cb69` nakednet, `--chain mainnet`.
   - Fund with about 0.01 ZEC (one run needs about 250,000 zat).
   - Wait for 3 confirmations, about 4 minutes at 75 s blocks.
5. **Re-run the demo-terms simulation with 75 s blocks.** Option A (spec §12) assumed about 25 s blocks.
6. If the demo runs after NU7:
   - Confirm that zingo `0a5cb69` carries the mainnet NU7 height (unverified).
   - Expiry becomes +120 blocks and blocks become 25 s.
7. Do not use Z3 for mainnet. Its Zebra 6.2.3 pin cannot follow past NU7, and a node needs about 300 GB and a 24–72 h sync.

## 7. Risks, mitigations, fallbacks

| Risk | Mitigation |
|---|---|
| The `zainod:0.10.2-no-tls` override fails inside Z3 (untested; its Z3 env vars were read and are still valid) | Return to the 0.6.0 pin. In the facilitator, when `height == tip`, check `GetBlock(tip)` for the txid; if it is absent, treat it as mempool. |
| Zallet beta.1 note-tree corruption at the NU6.3 boundary: `PutBlocksCommitmentTree … Insert(Conflict…)` (CHANGELOG L352-371; "most likely" with `zallet-zebra`, while Z3 uses `zallet-zaino`) | Set `Z3_ZALLET_IMAGE=zodlinc/zallet:v0.1.0-beta.3` and `[rpc] allow_insecure_remote_bind = true`, then `down -v` and redo §2. Unknown whether beta.3 accepts `as_of_version = "0.1.0-beta.1"`. |
| `Error: Please enter the wallet passphrase with walletpassphrase first.` or a backup gate | `require_backup = false` (step 3), and use account 0 from the CLI command |
| An opid is lost on restart, and the deposit is sent twice | Persist the txid at success. Recover through `z_listtransactions` by memo. |
| No blocks are mined | Run the block-clock loop as a supervised process |
| Zaino runs slowly under emulation | Accept it. The first-sight window is 30 s. |
| Z3's CI never sends a transaction; only `getwalletinfo` is checked (`ci.yaml` L123-283) | Time-box §2 to 60 minutes, then switch to a fallback |

**Fallback A (best): Zebra 7.0.0 built-in gRPC with zingo-cli.**
- Override the image with `zfnd/zebra:7.0.0` (native arm64).
- In `config/regtest/zebra.toml` add `[rpc] lightwalletd_listen_addr = "0.0.0.0:9067"` (experimental since 6.4.0) and publish port 9067.
- **Set NU5 through NU6.3 to 1.** zingo `--chain regtest` hardcodes every upgrade at 1 with NU7 off (`zingolib/src/config.rs` L98; `zingo_common_components` 0.4.0 `protocol.rs` L229-245).
- Fund with `generatetoaddress [3, zingoUA]`, then `generate [5]`.
- Both the facilitator and zingo use `http://127.0.0.1:9067`.
- Unknowns: whether 7.0.0 accepts the config, and whether zingo syncs against Zebra's gRPC.

**Fallback B: lightwalletd v0.6.0 on regtest Zebra.** Untested; no evidence it works.

**Fallback C (last resort, no chain):** FakeChain plus `zdecrypt build-test` (the `testbuild` feature) with real v6 transactions. Decryption is real, the chain is not.
