# z402 Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the client side of z402: the shared `@z402/protocol` package, the `@z402/client` x402 scheme with its zingo-cli wallet, the `@z402/testkit` fake chain, the demo agent, and the end-to-end harness. With them, a stock x402 v2 agent pays a stream of API calls in shielded testnet ZEC by adding one `register` line.

**Architecture:**
- `PrepaidVoucherScheme` implements x402's `SchemeNetworkClient`. It makes an on-chain deposit when headroom runs low, signs a cumulative Ed25519 voucher per call, and learns the facilitator's session state through the `schemeHooks.onPaymentResponse` hook. That hook also drives the stock wrapper's single recovery retry.
- Every byte format and every limit computation lives in `@z402/protocol`, which the facilitator agent imports too.
- The wallet is zingo-cli, driven by one-shot calls (the invocation proven on NU7 testnet). Confirmations are read from the same lightwalletd the facilitator uses.

**Tech Stack:** Node ≥ 22 (dev box: 26.11.0), pnpm workspace, TypeScript (strict, `NodeNext`), vitest, tsx, `@x402/core` + `@x402/fetch` 2.28.0, `node:crypto` Ed25519 (`@noble/curves` for test cross-checks only), zingo-cli (zingolib `0a5cb69`, Nym-free `nakednet-test-mode` build).

## Review Focus

1. **Real zingo-cli output differs from the source-derived expectations.** In one-shot mode, tracing writes ANSI-coloured ERROR lines to stdout ahead of the pretty-printed JSON, and stderr carries a WARNING banner and heartbeats. Expected: the adapter still finds the JSON reply. Pinned by Task 10's `extracts the JSON reply even when tracing lines precede it` and by Task 12's captured fixtures.
2. **A wallet error after the transaction was already broadcast** (zingo `Transmission error`). Expected: no second payment. Pinned by Task 11's `reconciles a Transmission error by memo without sending again`.
3. **The facilitator lists the deposit in `session.deposits` but never echoes it in `transaction`** (lazy credit). Expected: the client stops resending once the deposit is listed. Pinned by Task 6's `resendTxid() stops once the snapshot lists the deposit`.
4. **The app aborts or times out a `fetch`, so the hook never fires.** Expected: the session is not wedged. Pinned by Task 7's `safety release frees the mutex and advances cumulative after 120 s without a hook`.
5. **A malicious or misconfigured 402** (huge `windowZat`, `tutest1…` payTo, price above window). Expected: refused before any money moves. Pinned by Task 7's `rejects unsafe requirements before touching the wallet`.
